# 案例库规范

## 目标

把书中案例转化为可检索、可引用、能解释因果机制的研究卡片。案例库不等于故事摘要。

## 案例卡字段

| 字段 | 要求 |
| --- | --- |
| ID | `C-001` 起连续编号 |
| 案例主体 | 企业、人物、行业、产品或事件 |
| 时间与背景 | 只写来源支持的必要信息 |
| 起点 | 原有优势、约束、客户和价值网络 |
| 触发事件 | 技术、需求、竞争、政策或组织变化 |
| 关键决策 | 做了什么、没做什么，谁影响资源配置 |
| 因果机制 | 用一条可检验的因果链说明为何得到结果 |
| 结果 | 短期与长期结果；历史状态需注明时点 |
| 观点映射 | 支持、挑战或限定哪个核心命题 |
| 边界/反例 | 在什么条件下不可类推；是否存在相反案例 |
| 可复用角度 | 可用于哪些文章、课程问题或管理诊断 |
| 来源 | S1-S4 与来源定位符；外部更新另列 |

## 汇总视图

除案例卡外，至少生成：

1. “观点 → 案例”矩阵；
2. “案例 → 文章主题”索引；
3. 同机制案例组；
4. 反例和边界案例清单；
5. 可能过时、需要外部更新的案例清单。

## 质量规则

- 区分作者提供的事实、作者解释和本次迁移推论；
- 不补写书中没有的动机、对话、数字或结果；
- 不因企业后来成败倒推书中当时的因果；
- 同一案例跨章节出现时合并主卡，列出多个来源定位符；
- 案例只是理论证据的一部分，不把单个成功故事当普遍规律。

## 验收

每个案例必须有“因果机制、观点映射、边界、来源”四项；缺一项不得进入正式案例库。随机抽查至少 5 个案例回到原书核对。
