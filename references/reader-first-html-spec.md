## 1. 触发条件与目标

用户要求“拆书精要、总结网页、分享版、知识笔记、小红书风格、响应式网页、HTML 报告”时使用本规范。

目标不是复刻社交平台，而是把完整研究转化为目标读者愿意读、能够理解、便于保存和分享的知识产品。视觉风格必须服从阅读任务，不能用卡片、贴纸或动画掩盖内容空洞。

默认交付：

- `BOOK_ESSENTIALS.html`：可离线打开的单文件 HTML；
- `BOOK_ESSENTIALS_DESKTOP.png`：桌面端预览；
- `BOOK_ESSENTIALS_MOBILE.png`：手机端预览。

## 2. 目标读者两步推导

不要把网页对象机械设成“用户本人”，也不要在证据足够时反问用户。

### 第一步：推导书籍目标读者

按以下证据判断：

1. 书名、副标题和封面承诺；
2. 序言、导论中的问题定义；
3. 目录、案例主体和术语密度；
4. 出版定位、作者身份和推荐语；
5. 书中默认读者能采取的行动。

输出一条内部读者判断，例如：“企业管理者、创业者、产品与创新负责人，以及希望理解战略失灵机制的商学院读者。”

### 第二步：收窄当前分享场景

再根据媒介与任务收窄：

- 阅读时长：快速浏览、8 分钟精读或系统复习；
- 设备：手机优先、桌面研究或打印；
- 任务：理解概念、支持决策、课程讨论或社交传播；
- 认知状态：第一次接触、已读复习或需要引用素材。

最终页面服务于两步推导的交集。只有书籍定位互相冲突，或不同选择会显著改变篇幅、术语和交互时才询问用户。

## 3. 内容源与呈现层分离

建立一个经过审校的结构化内容源，再由渲染层生成页面。不要把事实、结论和引文散落在 HTML 模板中。

推荐三层：

1. 内容源：标题、摘要、原则、案例、金句、误读、自测、行动与证据说明；
2. 渲染器：只负责结构、转义、样式和交互；
3. 发布物：单文件 HTML 与预览截图。

这样可以独立验证内容数量、证据标签和页面结构，也便于更换视觉主题而不改写研究结论。

## 4. 页面内容合同

根据书的实际密度裁剪，但读者分享版通常按以下顺序组织：

1. 首屏：书名、副标题、核心矛盾、作者、版本、阅读时间、三条阅读收益；
2. 一句话摘要：解释“为什么值得读”；
3. 因果链或核心模型：让读者在 30 秒内看懂机制；
4. 关键原则：每条包含解释、观察信号和来源；
5. 案例剧场：起点、决策、机制、结果、边界和来源；
6. 金句墙：原句与编辑改写分开展示；
7. 常见误读：错误理解与书中校正并列；
8. 自测或诊断：把理论转成读者问题，并声明不是科学测评；
9. 行动清单：少量、具体、可执行；
10. 版本与证据：版本身份、旧版状态、关联著作、页码口径和证据等级。

不要为了凑固定数量编造原则、案例、金句或自测题。研究材料不足时缩短页面并声明边界。

## 5. 证据与发布边界

- **原句**：逐字核对的短引，保留 S1 来源定位符；
- **编辑改写**：明确标记 S3，不加引号，不写成作者原话；
- S2 综合：标明“跨章忠实综合”并列出关键页码；
- S4 内容：不得进入对外成品；
- 版本差异：保留 E1-E3 标签，E3 只能说明版本存在和待核查假设；
- 关联著作：明确写“关联著作，不是旧版”；
- 页码：声明是 PDF 物理页还是纸书印刷页。

发布前删除或改写以下内容：

- 本地绝对路径、用户名和临时目录；
- 内部测试报告名、脚本名和工作日志；
- 对智能体过程的叙述；
- 未核实的联网事实；
- 会让读者误以为已经取得旧版全文的表述。

## 6. 视觉与交互原则

知识笔记风格可使用奶油纸张底色、红色强调、黄色/薄荷绿/浅蓝便签色、黑色描边和轻量硬阴影。不要复刻平台导航、商标或内容流。

默认浅色主题，保证设计意图首次打开即可成立；可提供深色切换并记忆用户选择。不要直接跟随系统深色模式覆盖首次展示。

交互只保留能改善阅读的功能：

- 阅读进度；
- 桌面目录与当前章节高亮；
- 案例按机制筛选；
- 金句前后切换与复制；
- 管理者自测反馈；
- 回到顶部、主题切换和打印/PDF。

避免无意义轮播、自动播放、复杂转场和依赖外部脚本的装饰效果。支持 `prefers-reduced-motion`。

## 7. 响应式、离线与可访问性

默认采用移动优先和无外部资源依赖方案：CSS、JavaScript、图标和必要数据全部内嵌。若必须使用外部资源，先获得用户同意并提供离线降级。

最低要求：

- 单一 `h1`，章节层级连续；
- 所有目录锚点存在且唯一；
- 按钮有可读文本或 `aria-label`；
- 动态结果使用 `aria-live`；
- 键盘可操作，焦点清晰；
- 正文不横向滚动；
- 手机标题、元数据标签和卡片不越界；
- 提供 `@media print`，打印时隐藏导航与交互控件。

## 8. 构建与验证流程

1. 从研究成果建立结构化内容源，先检查条目数量和证据标签；
2. 为页面结构、离线性、锚点、证据边界和响应式规则编写失败测试；
3. 生成完整 HTML，运行解析与发布审计；
4. 用浏览器真实渲染，不以“代码看起来正确”代替视觉检查；
5. 至少生成 `1440 × 1100` 桌面截图和 `390 × 1000` 手机截图；
6. 检查首屏、目录、长标题、标签、案例卡、金句、自测、版本说明和底部工具；
7. 修复默认主题、字体回退、文字截断、横向溢出和固定工具遮挡后重新渲染；
8. 运行完整测试套件并记录成品大小、文件名和生成时间。

浏览器真实渲染是发布门槛，不是可选美化步骤。桌面通过不能推断手机通过，静态解析通过也不能推断视觉通过。

## 9. 验收清单

- [ ] 目标读者经过“书籍定位 → 当前分享场景”两步推导；
- [ ] 核心结论、案例、金句和版本说明与研究档案一致；
- [ ] 原句、编辑改写、S1-S3 和 E1-E3 边界清楚；
- [ ] 页面没有本地路径、内部日志和 S4 内容；
- [ ] `BOOK_ESSENTIALS.html` 可离线打开，无外部资源依赖；
- [ ] 默认浅色，主动切换主题后可记忆；
- [ ] 桌面与手机目录、文字、卡片、标签均无溢出；
- [ ] 案例筛选、金句、自测、主题和打印功能可用；
- [ ] 已生成并检查 1440 与 390 宽度预览；
- [ ] 自动化测试与浏览器真实渲染均通过。
